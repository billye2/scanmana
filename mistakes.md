# Mistakes log

Convention: every fixed mistake gets an entry here in the same change that fixes it.
Format: `- YYYY-MM-DD — what went wrong — how it was fixed / how to avoid it`
- 2026-09-20 — told Billy the Livermore change would ship as 1.2.10, then `npm run bump` rolled 1.2.9 to 1.3.0 (the script carries .9 into the next minor) and the commit title, help text, mistakes entry and HANDOFF all said 1.2.10. Fixed: prose corrected to 1.3.0 in a follow-up commit (the pushed commit title stays). Lesson: run the bump before quoting a version number.
- 2026-09-20 — the composite verdict was the worst of all four frameworks, so Livermore's "chasing" objection (more than 5% past the pivot) alone turned 836 deck cards to Pass; the research layer's first night showed those were the best cards on the deck (69% broke out in 10 sessions vs 67% for Wait, +16.5% vs +13.5% best close in 20), while every other framework's solo veto marked worse cards. Fixed (1.3.0): `overallVerdict` is the worst of Kullamägi, Darvas and Minervini; Livermore's paragraph stays on the card and his objection is still recorded in `scan_history.objections`, so /research keeps scoring it. Lesson: a veto in a composite rule needs its own measured hit rate; "past the pivot" is a description of the leaders in a momentum scanner, not a warning.
- 2026-09-20 — the first outcome labels put the deck's 10-day "breakout" rate at 72% for Wait and Pass alike: the level was the Livermore pivot, which sits *below* the close for the 2,300 deck rows that had already broken it, so those counted as broken out on day one (95%). Fixed: `research/outcomes.py` `breakout_level` uses the box top, else the pivot only while it is still overhead, else the 20-session high (a name past its pivot has to make a fresh high). Lesson: a hit-rate that does not separate the groups it was built to compare is a labelling bug, not a finding; sanity-check the base rate before reading the split.
- 2026-09-20 — split detection marked 19 gaps as `auto` (which rescales the scan's bars) and 828 as review; the auto list included −33% earnings drops (BRBR, ZUMZ) that matched a 3:2 ratio on price and volume alone. Fixed: a gap day whose range is >2.5× or whose volume is >4× what the share-count change explains "traded like news" and loses 0.3 confidence (stays in review at the top of the list), and the keep threshold rose to 0.5. 847 → 46 candidates, 9 auto. Lesson: anything that silently rewrites input data needs a false-positive gate that a plausible non-split cannot pass.
- 2026-09-20 — theme clustering on raw return correlation produced one 153-name cluster (the market) beside a few real groups. Fixed: `residual_returns` regresses the equal-weight market return out of every name before correlating; the same threshold then yields refiners, crypto treasuries, cybersecurity, gold miners. Lesson: cluster on what is left after the common factor, or the common factor is the only cluster.
- 2026-09-19 — the research-layer migration failed on first run: a semicolon inside a `--` comment in `db/schema.sql` ("writes scan_history; every…") split the comment into two bogus statements, because `scripts/migrate.ts` splits the file on `;` — the file's own header warns about exactly this. Fixed: comment rewritten without semicolons, plus a note at the top of the research block. Lesson: `db/schema.sql` comments are code as far as the migrator is concerned; no `;` outside statements.
- 2026-09-10 — the first paper-trading release armed a *buy-stop at the trigger* even when the last close was already above it (breakout-day cards, and any Take on such a card). A buy-stop below the market is an order no broker accepts; Billy caught it on the day it shipped. Fixed: `paper_orders.kind` is `buy_stop` or `market` — above the trigger the order is a market buy at the next open with the same stop, the Take button says "Take at open", and the auto book arms breakout-day cards the same way. Lesson: every paper order type must be one a real broker would take, or the rehearsal teaches the wrong habit.
- 2026-09-09 — the home page server-rendered every card's 130 bars into the HTML on every open (dynamic, uncached): 75 KB gzipped for a 27-card deck, ~96% of it bars the user would mostly never page to. Fixed: `slimDeck` keeps bars for the first card ± 1, the deck fetches the rest per card from `GET /api/scan/bars` (neighbours prefetched, browser-cached for the day); the /deck list page ships no bars at all. 75 → 12 KB gz (home), 75 → 4 KB (list). Lesson: when a page embeds a list of heavy items but shows one at a time, ship one and fetch the rest.
- 2026-09-09 — "Enable nightly scan alerts" gave no feedback at all: a missing key returned silently, a rejected subscribe or failed save was an unhandled promise, and a subscribed device showed nothing — so Billy tapped it on the iPhone, saw no permission prompt, and had no way to tell what happened (the only subscription in the DB was a desktop Chrome one from 2026-08-31). Fixed: every step reports on screen (enabling / on / error text), a subscribed device shows "Send test alert" (`POST /api/push/test`, that endpoint only), permission-denied explains the iOS Settings path. Lesson: a button whose effect is invisible (push, email, background job) must show its outcome, and ship a way to test it on the spot.
- 2026-09-09 — the bottom bar (1.1.9) was built from text buttons with unicode glyphs (‹ › ☆ ★ ↗) in uneven grid columns; iOS drew the glyphs in mismatched fallback fonts and the bar looked broken on the phone. Fixed: the same line-icon SVGs as the top nav, one equal column each, icon-only. Lesson: no unicode symbols as UI glyphs — the Icons.tsx rule ("no emoji, so they render identically on every platform") applies to arrows and stars too.
- 2026-09-07 — HANDOFF.md recorded another product's infrastructure (its database name, the shared Vercel project id, leftover env var names), which blocked making the repo public. Fixed: scrubbed the docs, moved those notes to private memory, squashed git history. Lesson: per-repo docs describe only that repo; cross-project infra notes go in private memory.
- 2026-09-03 — the empty-deck hint still said "tap Run scan **above**" two releases after the button moved below the deck (1.0.5). Fixed alongside the rename to "Run scan for previous day". Lesson: when a control moves, grep for prose that points at it.
- 2026-09-02 — the 02:30 UTC (9:30pm ET) cron never did any work: Massive's grouped-daily bars for the day are not published by then, so every night it fell back to the previous day, saw "already scanned", and the 05:30 UTC catch-up did the real scan. Fixed: first cron moved to `0 4 * * 2-6` (midnight EDT). Lesson: verify a cron actually wrote rows (`scan_results.created_at`), not just that it returned 200.
- 2026-09-01 — the analysis verdict had a "Take" level, but the app only ever sees end-of-day bars: by the time a breakout is visible the session is over, so "buy now" is never a decision the data supports. Fixed: `Verdict` is `wait | pass`; breakout-day branches say "buy tomorrow's open if it holds". Lesson: verdict vocabulary must match what the data can actually decide.
- 2026-09-01 — charts never rendered on the deck: `Chart` div was `h-full` inside a flex-1 parent under a `min-h-dvh` main, so its percentage height resolved to 0 and lightweight-charts was created 0px tall. Fixed: chart div is `absolute inset-0` in a `relative` flex-1 parent, plus `autoSize: true` with a 300px fallback. Lesson: percentage heights need a definite ancestor height; verify UI in a browser, not just by curl.
- 2026-09-01 — first manual scan failed: Massive free tier returns 403 "Attempted to request today's data before end of day" for the current ET date, and `fetchGroupedDaily` threw instead of walking back to the previous trading day. Fixed: that specific 403 is treated as "no data yet" (empty), so `runScan` falls back a day. Also added a 05:30 UTC catch-up cron (skips if already scanned) in case 02:30 UTC is before Massive's cutoff.
- 2026-08-31 — backfill died at 192/261 dates on a transient `SocketError: other side closed` from Massive; `lib/massive.ts` `get()` had no retry, so one dropped socket killed a 55-min job. Fixed: `get()` retries transient errors/5xx with backoff (2s→16s) and waits out 429s; 4xx stay fatal. Backfill was already resume-safe, so nothing was lost.
- 2026-08-31 — setup wizard and `vercel env pull` wrote secrets (API key, DB URLs, CRON_SECRET, VAPID private key) into `.env.local`. Policy is Vercel-env-only (`~/.claude/CLAUDE.md`). Fixed: wizard adds the key straight to Vercel; `npm run dev|migrate|backfill|scan:now` wrap in `vercel env run -e production`; dotenv removed from scripts; `.env.local` stripped to public VAPID values.
- 2026-08-31 — scripts loaded env via `dotenv/config`, which reads `.env` only, while Vercel pulls secrets into `.env.local` — DB scripts saw no DATABASE_URL. Fixed with `config({ path: [".env.local", ".env"] })`; only Next.js itself auto-loads `.env.local`, plain Node scripts never do.
- 2026-08-31 — deployed to the existing `rc02` Vercel project without first checking what its production alias served; it replaced an unrelated earlier deployment. Fix going forward: before the first `--prod` deploy onto a pre-existing Vercel project, inspect its deployments/aliases and confirm with the user. (Rollback path documented in HANDOFF.md.)
